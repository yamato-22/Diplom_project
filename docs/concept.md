Все взаимодействие с приложением ведется через API запросы.

Пользователи сервиса: покупатели и продавцы.
Пользователи могут регистрироваться, авторизоваться, менять свои данные (кроме e-mail), менять пароль.
Пользователь может иметь роль покупателя или продавца.

Клиент (покупатель):
формирует заказы, в каждом из которых представлены товары одного поставщика/продавца/магазина.
Покупатель может добавлять товары в заказ, получать детальную информацию о своем заказе, 
удалять товары из заказа, удалять заказ целиком до его подтверждения, 
подтверждать заказ для передачи поставщику в работу, 
Получает по е-mail сообщения об изменении статуса заказа поставщиком.


Поставщик(продавец):
Может добавлять товары в каталог, удалять, редактировать товары, добавлять/удалять свойства товаров,,
загружать товары в базу данных.
Получает подтвержденные покупателем заказы, с товарами из его магазина, 
Меняет статус заказа по мере его обработки.

Аутентификация пользователей:
Для аутентификации пользователей используются JSON Web Tokens (JWT).

Пользователь шлет логин/пароль на /api/user/token/.
Сервер проверяет их и генерирует два токена: Access и Refresh. 
Access Token — короткоживущий (время жизни настраивается, например - 60 минут). 
Он содержит в себе закодированные (payload) данные пользователя (user_id, username) 
и используется для доступа к защищенным эндпоинтам. 
Передается в заголовке Authorization: Bearer <токен>. 
Refresh Token — долгоживущий (время жизни настраивается, как правило - это день и более). 
Он не содержит payload, а служит только для получения новой пары токенов, когда access истек.

Клиент использует access token. Когда он истекает, 
клиент не заставляет пользователя снова логиниться, 
а отправляет refresh token на /api/user/token/refresh/ и получает новую пару.
